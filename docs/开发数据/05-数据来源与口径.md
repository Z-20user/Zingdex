# 数据来源与口径

这份档案的每条数字都能追溯。下面是追法。

---

## 一、数据取自哪里

| 数据 | 来源文件 | 取法 |
|---|---|---|
| 版本号、变更内容 | `动效-分享版本\00_先读我\版本记录.md` | 直接引用原文 |
| 构建时间 | `动效-分享版本\06_旧版本备份\` 下每个文件的**修改时间** | 文件系统时间，精确到分钟 |
| 体积 | 同上目录，文件实际大小 | 字节数换算 MB |
| 补丁历史（旧的） | `动效-分享版本\10_开发记录\VERSIONS.md` | 只到 1.11.0，作为交叉核对 |
| 工程流程、防护体系、服务端方案 | `10_开发记录\开发流程与防护体系报告.md` | 第六节完整引用其结论 |
| 架构、单点真相、构建命令、下一步 | `10_开发记录\HANDOFF.md` | 直接引用 |
| 当前产物与签名 | `HANDOFF.md` + 实际文件核对 | 两者一致才写 |

## 二、事实、推断、预测的边界

| 等级 | 在本档案里的位置 | 例子 |
|---|---|---|
| **事实** | `01` 时间线、`02` CSV、`03` 快照 | 「v1.12.3 修复了安装包尾标记 24/32 字节不一致」 |
| **推断** | `01` 的「这一阶段的判断」、`04` 第三节 | 「性能重构放在最前面，后面才有条件加内容」 |
| **预测** | `04` 第一、二节之外的排期 | 「一个月内可完成安装包瘦身」 |

`04-后续路线.md` 里每条都标了 ✅ / 🟡 / ⚠️，看标记即可区分。

---

## 三、已知偏差（写清楚，避免误读）

1. **时间只到分钟**。同一分钟内的先后无法区分。
2. **v1.12.27 不在备份目录里**。它是最新版，产物在 `01_电脑版` 与 `02_安卓版`，体积取当前文件实测值（117.2 MB / 2.2 MB）。
3. **号段不连续**。缺 1.12.5 / 7 / 8 / 10 / 11 / 22 / 24 / 26，原因无法从文件判定，档案按「有文件才算」处理。
4. **密钥 App 的版本号有跳号**（0.0.1.2 → 3 → 5 → 6 → 7 → 8），缺失的 0.0.1.4 可能只存在于安装记录中。
5. **体积含打包开销**。安装包 111–112 MB 是「站点 + 运行时 + 安装器」，不等于内容本身。
6. 控制台输出中文可能显示为乱码，不影响文件内容；`02-版本与产物数据.csv` 用 UTF-8 BOM 保存，Excel 直接打开不乱码。

---

## 四、隐私处理

- 本档案**没有引用任何密钥内容**：只写「10000 枚普通码 / 1000 枚 S 级」这类数量，不出现具体码值。
- 不记录签名口令、令牌内容、联系人信息。
- 路径按本机实际写法保留（换机时需要改），未做脱敏——这份文件只在本机使用，未上传。

---

## 五、复现方式

想重新生成 `02-版本与产物数据.csv`：读取 `06_旧版本备份` 下所有 `.apk` / `.exe`，用文件的 `mtime` 作为构建时间、`size` 作为体积、文件名里的 `vX.Y.Z` 作为版本号即可。版本要点需要人工对照 `版本记录.md` 填写，无法自动提取。
