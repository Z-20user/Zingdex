# 02 · 检索手册（必须查得到）

这份手册的目标只有一个：**任何一次「我想找某个动效」，都要有确定答案，不能出现「查不到」。**

---

## 一、按这个顺序查，不要跳步

| 顺序 | 手段 | 适用 | 命令 |
|---|---|---|---|
| 1 | 索引文件 | 有了 `index.json` 后最快 | `grep -i 关键词 index.json` |
| 2 | 检索工具 | 按场景 / 设备 / 类别筛 | `node tools/find-motion.js <库> 关键词` |
| 3 | 源码直搜 | 工具不可用时 | `grep -o '"zh":"[^"]*"' engine.js` |
| 4 | 应用内浏览 | 全都没装 Node 时 | 打开 APK / exe，搜索框输入 |

**永远从 1 开始。** 前三步都不依赖浏览器，纯命令行可完成。

---

## 二、关键词怎么写

同一个东西至少有三种叫法，**先试名词，再试场景，最后试类别**：

| 你想要 | 第一轮 | 第二轮 | 第三轮 |
|---|---|---|---|
| 列表逐项出现 | `列表` | `逐项` `错峰` `stagger` | `--cat 列表` |
| 加载转圈 | `加载` | `进度` `loading` | `--cat 循环` |
| 卡片浮起 | `卡片` | `抬起` `浮起` `lift` | `--cat 入场` |
| 按钮反馈 | `按钮` `点击` | `反馈` `press` | `--cat 状态` |
| 页面转场 | `转场` `页面` | `路由` `切页` | `--cat 退场` |

**规则**：
1. 先中文，不中再英文（`list` / `card` / `loading` / `press`）
2. 再不行就用**宽词**（`动画` 这种没用的词不要用）
3. 都没有 → 用 `--list` 直接看 500 个特效编号

---

## 三、查不到时的逐级降级

```
① 关键词太窄  → 换更短的词（「电商商品列表」→「列表」）
② 设备筛死了  → 去掉 --device
③ 类别筛死了  → 去掉 --cat
④ 时长卡死了  → 去掉 --max
⑤ 数据没读到  → 检查 <库目录>/assets/engine.js 是否存在
⑥ 版本对不上  → 用 --list 看实际有哪些编号，按实际来
```

**任何一步都失败时，必须回到 `--list` 看清实际数据**，不要凭记忆编 id。

---

## 四、检索结果怎么用

`find-motion.js` 输出：

```
● 商品列表 [s001] 电商零售
   · 入场 上滑入场 380ms out fx-s001-07
```

- `[s001]` 是**场景 id**
- `fx-s001-07` 是**条目编号**
- 想取代码：先看 `mc`（类别）→ 再从 `--list <族>` 找对应族的编号 → `extract-motion.js`

> 两者之间没有公开映射表，这是当前实现的已知缺口。
> 稳妥做法：**在应用详情页复制代码**，或先 `--list` 按族挑一条语义接近的。

---

## 五、输出契约（给 AI 的硬要求）

回答用户时必须包含：

1. **场景**：中文名 + id（如「商品列表 s001」）
2. **条目**：中文名 + 时长 + 类别（如「上滑入场 380ms 入场」）
3. **代码**：三件套齐全，或明确说明「该条无需 JS」
4. **适配**：目标设备的时长系数与禁用项（见 `04-device-rules.md`）
5. **来源**：引用的是哪个文件、哪个编号

缺任何一项，等于没查完。

## 六、自查

- [ ] 用的是实际查到的 id，不是猜的
- [ ] HTML 与 CSS 的类名对得上（`fx-<id>`）
- [ ] 时长按目标设备乘过系数
- [ ] 没有在手表/车机上用被禁用项
- [ ] 说明了是否需要 JS
